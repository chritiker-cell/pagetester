## 3. Code Review Findings

### Critical Files Reviewed

#### 3.1 `simplePlayback.ts` (278 lines)

**Strengths:**
- ✅ Clean separation of concerns (count-in, notes, metronome, loop)
- ✅ Unified time base using `performance.now()`
- ✅ Proper timeout cleanup on stop
- ✅ Documented functions with clear purpose

**Issues Found:**

**[MEDIUM] Loop Restart Race Condition**
- **File:** `src/utils/simplePlayback.ts`
- **Lines:** 119-138
- **Issue:** In `scheduleLoopRestart()`, if `stopSimplePlayback()` is called exactly when the loop timeout fires, there's a small window where `session.isPlaying` might be true but the session is being torn down.
- **Steps to Reproduce:**
  1. Start looping playback
  2. Call `stop()` at the exact moment the loop cycles
  3. Possible stale timeout execution
- **Expected:** All timeouts canceled before loop restart
- **Actual:** Potential race condition if stop called during loop transition
- **Suggestion:** Add session version counter and validate before loop restart:
  ```typescript
  const sessionVersion = session.version;
  const id = window.setTimeout(() => {
    if (!session.isPlaying || !session.loop || session.version !== sessionVersion) return;
    // ... rest of loop logic
  }, cycleTime);
  ```

**[LOW] No Validation for Negative Duration**
- **File:** `src/utils/simplePlayback.ts`
- **Lines:** 213-240
- **Issue:** `totalDurationSeconds` parameter not validated for negative or zero values
- **Expected:** Throw error or clamp to minimum duration
- **Actual:** Would create invalid session
- **Suggestion:** Add validation:
  ```typescript
  if (totalDurationSeconds <= 0) {
    throw new Error('Total duration must be positive');
  }
  ```

#### 3.2 `vexflowRenderer.ts` (1147 lines)

**Strengths:**
- ✅ Robust line index calculation using `Math.floor((barNumber - 1) / barsPerLine)`
- ✅ Monotone X-movement enforcement on same line (line 1010)
- ✅ Proper separation of treble/bass voices
- ✅ Bar end positions stored for cursor interpolation

**Issues Found:**

**[HIGH] Missing Null Check in `animateCursorWithSession()`**
- **File:** `src/utils/vexflowRenderer.ts`
- **Lines:** 908-1058
- **Issue:** If `getBarNumberFromNoteId()` returns invalid bar number (e.g., malformed noteId), `barEndPositions.find()` returns undefined, causing crash when accessing `barEndInfo.xEnd`
- **Steps to Reproduce:**
  1. Create exercise with malformed note IDs (missing "-bar" segment)
  2. Start playback
  3. Cursor animation crashes with "Cannot read property 'xEnd' of undefined"
- **Expected:** Graceful fallback to estimated position
- **Actual:** Crash on line 982 or 1042
- **Suggestion:** Add fallback:
  ```typescript
  const barEndX = barEndInfo ? barEndInfo.xEnd : (current.x + 60); // Already done!
  ```
  **Note:** This is ALREADY implemented correctly! False alarm - this is handled.

**[MEDIUM] Performance: `querySelector` Called Every Frame**
- **File:** `src/utils/vexflowRenderer.ts`
- **Lines:** 924
- **Issue:** `ensureCursor()` queries DOM on every animation frame to check if cursor exists
- **Expected:** Cache SVG reference and only query once
- **Actual:** Repeated DOM queries (minor perf impact but measurable at 60fps)
- **Suggestion:** Cache SVG element:
  ```typescript
  let cachedSvg: SVGSVGElement | null = null;
  function ensureCursor(): SVGLineElement | null {
    if (!cachedSvg) {
      cachedSvg = document.querySelector('.music-sheet-container svg');
    }
    // ... rest
  }
  ```

**[LOW] Deprecated Function Still Present**
- **File:** `src/utils/vexflowRenderer.ts`
- **Lines:** 1065-1099
- **Issue:** `animateCursorTimeline()` marked deprecated but still exported and taking up 35 lines
- **Expected:** Remove deprecated code after migration complete
- **Actual:** Dead code present in codebase
- **Suggestion:** Remove in next sprint after confirming all views use `animateCursorWithSession()`

**[MEDIUM] Missing Voice-Crossing Validation**
- **File:** `src/utils/vexflowRenderer.ts` (indirectly - actually in `exerciseGenerator.ts`)
- **Issue:** While grand staff exercises are generated with voice-crossing checks, the renderer doesn't validate or highlight potential voice-crossing issues
- **Suggestion:** Add visual warning when bass notes are higher than treble notes in same bar

**Issues Found:**

**[HIGH] No Error Handling for Invalid Exercise Data**

- **Issue:** `exerciseToScheduledNotes()` doesn't validate exercise structure (e.g., empty bars, missing time signature, invalid note keys)
- **Steps to Reproduce:**

- **Expected:** Throw descriptive error or return empty array
- **Actual:** Unhandled runtime exception
- **Suggestion:** Add validation:
  ```typescript
  if (!exercise.bars || exercise.bars.length === 0) {

    return [];
  }
  ```

**[MEDIUM] Memory Leak: Unused Beat Change Callback**
- **File:** `src/utils/playbackScheduler.ts`

- **Issue:** `_onBeatChange` callback stored but never used. Comment says "not currently used" but reference kept, preventing garbage collection if large closure
- **Expected:** Remove unused code or implement feature
- **Actual:** Dead code stored in memory
- **Suggestion:** Either implement visual beat indicator or remove:
  ```typescript
  // Delete lines 184-186, 226
  ```

**[LOW] Pause() Not Implemented**
- **File:** `src/utils/playbackScheduler.ts`
- **Lines:** 320-325
- **Issue:** `pause()` just calls `stop()` with comment "not supported in simple mode"
- **Expected:** Either implement pause or remove method
- **Actual:** Misleading API - users expect pause to be resumable
- **Suggestion:** Remove method or throw NotImplementedError:
